# Fresh signed-integer conversion reproduction

`Fresh.v` imports the dependency closure of the original `Int8.toBitVec_not` declaration from line 1. `Adjacent.v` independently imports the corresponding Int16/Int32/Int64/ISize negation theorems and Int8 and/or/xor theorems. Neither driver loads a prefix or checkpoint, skips declarations, or replaces a Lean proof. Both use strict failure and a 30-second per-line timeout.

The original declarations are `rfl` proofs generated by `declare_bitwise_int_theorems` in Lean's `src/Init/Data/SInt/Bitwise.lean`, lines 23–26. Their original bodies and dependencies are exported directly; there is no synthetic theorem or altered Lean source.

## Kernel repair

The unmodified target timed out at line 22,341 with the previous worker, both
in the manual fresh launcher and in the focused harness (30-second line limit).
The full cslib export places this declaration at line 3,842,943.

The trace isolates conversion call 2060. `BitVec.not` exposes a constructor,
but the experimental early record-eta path leaves `Int8.toBitVec` folded and
starts comparing fields. That descends into `Nat.bitwise` and well-founded
recursion: the sampled trace exceeds eight million conversion steps.

The fix tries delta before **general record eta**. The existing eta probe
remains a fallback if comparison after unfolding fails. Keeping the probe's
original record-type information matters for stuck computations with unit
fields. The checked unit shortcut, constructor-wrapper exclusion, and
unit-field eligibility conditions are unchanged. Trying delta first matches
upstream Rocq's priority at this point, also consistent with pinned Lean's
`type_checker.cpp:1081–1114` (lazy delta precedes structural eta).

No importer, Lean proof, arithmetic reduction, universe constraint, dependency
budget or transparency rule changes. Full weak-head reduction is unchanged;
an additional single-step reduction change was unnecessary.

With eta ordering alone repaired, the same declaration checks in about
17 milliseconds (`eta-order-trace/run.log`, declaration CPU timestamps).
The complete fresh target import and the seven adjacent theorems also pass.
This is a dependency-only result, **not full cslib acceptance**.

The baseline source and executable are preserved as `conversion.ml.before`
and `rocqworker.baseline.exe`; logs are evidence, not checkpoint inputs.
