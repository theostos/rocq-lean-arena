# Time spent rebuilding the dependency cache

One diagnostic replay of NDJSON lines 9,000,001–9,239,031, using the existing
9M checkpoint and the original `MathlibTo10000000` module name. No declarations
are skipped or replaced. The failing target retains its 1,800-second timeout.

The diagnostic worker has the restored transitive dependency cache. Only
`kernel/environ.ml` is instrumented; no importer changes or kernel-interface
changes are needed. The normal resume worker is restored before launch.

The counters measure CPU time in all dependency queries and, separately, cache
construction. Nested construction is counted only once; interrupted calls are
included. All construction is measured, including newly demanded entries—not
only cache entries lost at a checkpoint.

Snapshots are emitted after a query when at least one CPU second has elapsed,
plus at process exit. Existing declaration traces locate the target interval.
The generated report gives conservative timing bounds for unsampled boundary
work, rather than presenting interpolated numbers as exact measurements.

The runner uses the existing exclusive launcher lock and a single 16 GiB,
no-swap memory-guarded worker. It does not resume the full loop or alter any
checkpoint, seal or source. No model monitors it; the report is generated by
Python when the worker exits. No debugger or conversion-pair trace is enabled.

```sh
bash work/mathlib-cache-measurement/start.sh
```

While running: `latest/run.log`. After completion: `latest/REPORT.md` and
`latest/measurement.json`. Invocation hashes are in `latest/invocation.json`.
Do not launch another import while the measurement holds the launcher lock.

Validation: `validation-zrwximrk/` checks cache semantics with profiling on/off
and forces an interruption during cache construction. Both interrupted timers
are counted and nesting returns to zero. `test_report.py` checks interval
bounds, post-target exclusion and incomplete runs.

Timing/counter overhead can slow the diagnostic run. The result attributes CPU
time; it does not establish a full-run speedup or measure the cache's RAM size.
